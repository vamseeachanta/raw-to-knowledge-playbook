### claude

- **MAJOR — The private-field placeholder grammar, the plan's headline deliverable, is never enumerated.** The Deliverable (line 113) and title promise a "closed private-field placeholder grammar," and tests assert it (`test_private_placeholder_values_are_closed`, line 274: "Closed values pass; invented placeholder values fail"). But nowhere does the plan state *what a valid placeholder value looks like* — no literal example, no format/pattern, no concrete placeholder→term mapping rule beyond "placeholder fields are mapped to #65 private source field terms" (pseudocode line 171). I grepped the repo: no existing placeholder convention exists (`grep -rniE "placeholder|<<|REDACTED"` over `artifacts/`/`scripts/`/`config/` returns only the schema's `scope` string). This is asymmetric with the public-token side, which *is* fully pinned (`pst_` + 32 lowercase hex, line 161). An implementer must invent the placeholder grammar, which is non-deterministic and reintroduces exactly the drift the plan claims to police. A prior round already forced the token grammar to be pinned (Adversarial Review Summary, line 345: "token grammar was unpinned"); the placeholder grammar deserves the same treatment.
- **MAJOR/blocker-adjacent — `fixture_set_id` is declared a "closed enum" but specified as open-ended.** Pseudocode line 150: "fixture_set_id is a closed enum, initially wave0_public_token_good." The word "initially" contradicts "closed." `test_generation_request_marker_values_are_closed` (line 264) and the acceptance criterion (line 309, "fixture IDs are closed") cannot be made deterministic against an enum whose membership the plan declines to fix. Either enumerate the complete set or the closedness tests validate a moving target.
- **MINOR (risk) — "temp files" for negative fixtures is underspecified against a recursive scanner.** The plan repeatedly says unsafe examples are "written to temp files" (lines 40, 205, 290). I confirmed `validate_public_artifact_paths` recursively walks any directory argument via `rglob("*")` (line 723). If a test writes its transient unsafe content anywhere *under* a scanned root (e.g. inside `tests/fixtures/ace-public-token-fixtures/`) rather than the system temp dir, the parent scan will read it and fail nondeterministically. The plan should mandate temp files outside the repo tree (e.g. `tempfile.mkdtemp()` under `/tmp`), not merely "temp files."
- **MINOR — Readiness self-contradiction in the plan's own status.** Line 3 marks Status: draft; the Adversarial Review Summary (line 355) states "Overall result: MAJOR - draft only; not ready for `status:plan-review`." Gemini returned UNAVAILABLE for all three rounds (lines 347, 350, 353), so only two providers (Claude, Codex) ever produced signal — there is no independent third-provider quorum behind the "patched" claims. This is honest disclosure, not a hidden defect, but it independently precludes an APPROVE verdict and should be resolved (fresh active-provider re-review with no unresolved MAJOR) before promotion.
- **MINOR (cosmetic) — `count` range vs `fixture_row_id` width are unrelated but presented together.** Pseudocode lines 152-153: `fixture_row_id` matches `fixture_row_<three digits>` (000–999) while `count` is 1–100. Not contradictory (row id and generation count are independent), but the plan never states the relationship, leaving an implementer to guess whether row ids beyond 100 are reachable. Worth one clarifying sentence.
- **Checks that passed (stated per silence-is-failure rule):** I attempted to falsify the plan's retrieval claims and could not break these — the #65 schema field vocabulary the contract "imports" all exists exactly as cited; the `--scan-public-path` CLI flag exists and behaves as the plan assumes; the `pst_[0-9a-f]{32}` parent-scanner regex is genuinely *assignment-only* (line 127 requires `public_source_token[:=]`), so the plan's careful distinction between parent-scanner parity and #66-only bare-literal rejection (line 313) is accurate; `SOURCE_LIKE_RAW_DIGEST_PATTERNS` and `PRIVATE_SOURCE_FIELD_ASSIGNMENT_PATTERNS` are assignment/value-scoped (not bare-substring), so naming the terms as list values under neutral keys is genuinely scan-safe; `.rglob`/`os.walk` are in `DENIED_TRAVERSAL_PATTERNS` and the exemption is hard-wired to the parent scanner's filename, so the plan's "avoid recursive traversal in new source files" rule is correct and necessary; all five referenced issues are OPEN; the #66 split row exists; all 12 review artifacts exist with matching names; CI uses plain `uv run python`.
