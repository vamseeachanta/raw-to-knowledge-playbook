## Findings

### MAJOR

**M1 — The "live GitHub status" acceptance gate is not enforceable by the proposed CI validator.**
Acceptance criterion (line 149): *"No child issue is represented as implementation-ready unless **live GitHub status** and `.planning/plan-approved/<issue>.md` both prove user approval."* The proposed enforcement is `scripts/validate_ace_epic_wave_coordination.py` wired into `.github/workflows/validate.yml` (lines 119-120). I verified `validate.yml` runs on stock `ubuntu-latest` runners (`actions/setup-uv`, no `gh` auth step, no `GH_TOKEN`), and `ACE_SHARE_ROOT` is unset in this environment. A CI validator in that context **cannot query live label state**. The plan itself concedes this in Risks (line 177 — "can drift… unless the validator checks both repo-local fields and live issue state or clearly records a snapshot timestamp") but **leaves it as an open risk rather than a decision**. The load-bearing gate of the entire plan is therefore specified in a form its own implementation cannot deliver. Decide: (a) validator checks repo-local snapshot fields + a recorded snapshot timestamp, or (b) a separately-authenticated job re-reads labels. As written, criterion 149 fails closed in CI for the wrong reason or passes vacuously.

**M2 — TDD list does not cover acceptance criteria #62/#63 *per-wave* dependency binding.**
Acceptance criteria 156-157 require that **each** manifest-sampling wave is gated on #62 and **each** publishing wave is gated on #63. But the dependency test `test_dependencies_include_wave0_and_lifecycle_contract` (line 136) only asserts dependence on **#51 and #61**. The only #62/#63 tests (`test_manifest_snapshot_gate_listed`, `test_public_redaction_canary_gate_listed`, lines 141-142) check that the gate is *"represented"* somewhere in the table — not that a given child row that samples a manifest *depends on* #62, nor that a child row that publishes *depends on* #63. A coordination doc could pass every test in the list while violating acceptance criteria 156-157. This is a genuine test-vs-spec gap: implementation driven by the TDD list would not detect the omission. Add per-row dependency assertions tying manifest-backed waves → #62 and publishing waves → #63.

Align the pseudocode/test language with "records/asserts gate state" rather than "blocks," or specify the actual out-of-band enforcement (e.g., branch protection / required-status-check) that does the blocking.

The gate (lines 99, 149) depends on this marker convention, which the repo `docs/plans/README.md` also references but hasn't materialized. Not a blocker (no child is approved, so fail-closed is correct), but the validator must explicitly handle the missing-directory case as "all blocked" rather than crashing — state this in the plan.
