## Findings
1. **MAJOR - `control_plane_verification_state` is not actually separate from `parse_status`.**
Evidence: `docs/plans/2026-06-30-issue-65-ace-wave-0-ledger-schema-route-store-matrix.md:120-125` includes `rejected` while claiming “this enum is not ... the page-shape parse_status enum.” `docs/plans/2026-06-30-issue-65-ace-wave-0-ledger-schema-route-store-matrix.md:187` says parse-status values are not accepted in that field. But `docs/07-data-governance.md:44-47` and `skills/page-shape-contract/SKILL.md:37-38` already define `rejected` as a trust/parse-status value.
Why it matters: the planned test is logically inconsistent: it must accept `rejected` and reject page-shape `rejected` as the same bare string.
Required fix: rename the control-plane value, e.g. `review_rejected`, or change the plan to require field-qualified validation and explicitly test the overlap.

2. **MAJOR - The planned JSON schema can self-block the public scanner when it names private provenance fields as JSON keys.**
Evidence: the plan requires `artifacts/ace-wave0-ledger-schema.json` to be scanned (`docs/plans/2026-06-30-issue-65-ace-wave-0-ledger-schema-route-store-matrix.md:148-154`, `214-215`) and says private source names are schema terms (`:127`, `:189`). The existing scanner flags private source field assignments via `scripts/validate_ace_epic_wave_coordination.py:115-128`. Regex probe showed `[private-source-field-json-key-token] => True`, while `[private-source-field-array-term-token] => False`.
Why it matters: a natural JSON schema shape using `"source_sha256"` as an object key will fail the very scan the plan requires.
Required fix: specify a scanner-safe schema representation, or add a narrow schema-declaration allowlist with tests proving the committed schema JSON passes while real assignments fail.

3. **MAJOR - Approval-marker semantics are underspecified for the split registry.**
Evidence: the plan only says `.planning/plan-approved/<issue>.md` must exist with “required approval-marker fields” (`docs/plans/2026-06-30-issue-65-ace-wave-0-ledger-schema-route-store-matrix.md:137-138`, `193`, `211`). Existing semantics are stricter: `scripts/validate_ace_epic_wave_coordination.py:432-459` requires matching issue URL, exact plan path, 40-char reviewed commit, and existing review artifact bullets with valid verdicts; tests cover malformed markers at `tests/test_validate_ace_epic_wave_coordination.py:393-457`.
Why it matters: #65 could implement a weaker readiness gate for #65-#69 than the parent validator, reopening self-approval or stale-review risk.
Required fix: require reuse of the parent `validate_approval_marker` behavior or enumerate the exact same constraints in the plan and tests.

4. **MINOR - Conditional changed-skill scanning has a known self-blocker.**
Evidence: the plan may modify `skills/content-triage-and-exclusion/SKILL.md` (`docs/plans/2026-06-30-issue-65-ace-wave-0-ledger-schema-route-store-matrix.md:173`) and requires scanning “every changed bound skill doc” (`:152`, `:214`). The current scanner rejects `skills/content-triage-and-exclusion/SKILL.md:49`; command output reports a confidentiality-marker hit such as `[confidentiality-marker-token]`.
Why it matters: if #65 updates that skill, the required scan fails on pre-existing policy prose unless the plan accounts for it.
Required fix: either route that skill change to a follow-on issue, or add a precise policy-prose allowlist/sentinel and tests before making it a #65 scan target.

5. **MINOR - Route enum ownership remains ambiguous.**
Evidence: `docs/plans/README.md:15` says route targets are owned by #51, while the #65 plan says #65 “will define the schema and route-store vocabulary” (`docs/plans/2026-06-30-issue-65-ace-wave-0-ledger-schema-route-store-matrix.md:29`) and acceptance says the #65 schema “defines” closed route targets (`:205-208`).
Why it matters: downstream issues may treat #65 as the route authority instead of a schema encoding of the #51-owned contract.
Required fix: add field-level ownership metadata and tests asserting #65 only encodes #51-owned route targets.
