## Findings

### 1. [MINOR] The "import and call the parent" strategy — the fix for Claude r2 #1 — is under-specified for a repo where `scripts/` is not a package.
- **Evidence:** Plan acceptance line 227 and pseudocode line 142 require the new `scripts/validate_ace_wave0_schema_contract.py` to pass `scripts/validate_ace_epic_wave_coordination.py::validate_approval_marker` "by import/call," and pseudocode line 157 requires invoking the parent `validate_public_artifact_paths`. But there is no `scripts/__init__.py` (verified: `ls scripts/__init__.py` → not found), so a literal `from scripts.validate_ace_epic_wave_coordination import …` is not guaranteed across run contexts. The parent's own test sidesteps exactly this by loading the module via `importlib.util.spec_from_file_location(...)` (`tests/test_validate_ace_epic_wave_coordination.py:19`). Under `python -m unittest tests.test_validate_ace_wave0_schema_contract` from repo root (the command in acceptance line 236), `scripts/` is not on `sys.path` and is not an importable package.
- **Why it matters:** This is the mechanism that resolves the self-approval risk (codex r1 #3 / Claude r2 #1). If the implementer follows the prose literally with a package-style import, the new test fails to load the parent at all, and the path of least resistance becomes re-deriving the marker checks locally — reintroducing the weaker-gate vector the patch was meant to close.
- **Required fix:** State the import mechanism explicitly: reuse the established `importlib.util.spec_from_file_location` load (or a documented `sys.path` insertion) so both the validator-as-script and the unittest-from-repo-root contexts load the parent module, and add a TDD assertion that the parent symbols are the ones actually invoked.

### 2. [MINOR] The verification-state disjointness check has no machine-readable comparison source, so #65 will hardcode the #61/#63 sets and the check fails open on future drift.
- **Evidence:** Plan lines 122/198/224 require the `control_plane_verification_state` enum to be "disjoint from #61 lifecycle states and `page-shape-contract` `parse_status` values" by exact set membership. But those comparison sets exist only as prose owned by other issues: lifecycle (`candidate, provisional, verified, rejected, superseded, stale_requires_rescreen`) at `docs/plans/README.md:16` (owned by #61), and `parse_status` (`verified | provisional-unverified | deferred | rejected`) at `docs/03-verification-playbook.md:91` and `skills/page-shape-contract/SKILL.md:37`. There is no parseable registry for either; the plan gives the #65 validator no source to read.
- **Why it matters:** #65 takes responsibility for a cross-check whose inputs it does not own. A hardcoded copy that drifts when #61 or #63 extends its enum will fail *open* — silently missing a future collision — which is precisely the "registries could drift" failure mode the plan guards against for the wave registry (it compares against `ace-share-ingestion-wave-coordination.md`) but does not extend here.
- **Required fix:** Name the authoritative source the #65 validator pins or reads for the lifecycle / `parse_status` sets, and record (in the schema's `public_safety_notes` or a TDD row) that #61/#63 own the master lists so a stale copy is a documented, tested limitation rather than a silent fail-open.

### 3. [MINOR] The public-scan coverage test does not distinguish always-present core artifacts from conditional ones, and `validate_public_artifact_paths` errors on any missing path.
- **Evidence:** `validate_public_artifact_paths` appends `"missing public artifact scan path: {root}"` for any non-existent path (validator lines 718–719). The plan's path list mixes always-present artifacts (plan, README, coordination, schema, validator, tests, workflow — pseudocode lines 158–160) with conditional ones ("every changed bound skill doc, and every retained …*plan-65*.md artifact … when they exist" — acceptance line 230). The coverage test `test_public_scan_paths_cover_65_artifacts` (TDD line 207) asserts the list "is passed to the scanner … when present" without separating the two classes.
- **Why it matters:** If the implementer pre-filters everything to "existing paths only" (needed so absent conditional artifacts don't break CI), then a *core* artifact the implementer forgot to enumerate is silently skipped and a leak in it escapes — a "test that cannot catch leaks." If instead nothing is filtered, an absent conditional skill/review artifact fails CI spuriously.
- **Required fix:** Specify that the core set is scanned unconditionally (and the coverage test asserts each core artifact is present in the list), while only conditional paths (changed skills, retained review artifacts) are filtered to existing files.
