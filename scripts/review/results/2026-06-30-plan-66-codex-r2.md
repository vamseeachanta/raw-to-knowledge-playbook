## Findings
1. `docs/plans/2026-06-30-issue-66-ace-public-token-fixtures-private-field-placeholders.md:131-135` does not define a closed generation-request marker grammar. It says the marker key is `public_source_token_request`, contains “fixture-local ids only,” and the generator accepts “fixture count and fixture set id only,” but gives no JSON shape, required keys, allowed value regex, max length, allowed file location, or closed fixture-set ID vocabulary. The TDD rows at `docs/plans/2026-06-30-issue-66-ace-public-token-fixtures-private-field-placeholders.md:229-233` also do not require a case where a source/path/name/hash is smuggled inside the allowed `fixture_set_id`/local-id value. Since `scripts/validate_ace_epic_wave_coordination.py:106-128` only catches specific leak patterns, arbitrary private-like names can pass as “fixture-local” unless the plan makes that term mechanical.

2. `docs/plans/2026-06-30-issue-66-ace-public-token-fixtures-private-field-placeholders.md:150-156` and `:272-274` overstate the private-source-term invariant as applying to “every committed artifact,” while the current scanner explicitly allows schema-term prose. `tests/test_validate_ace_epic_wave_coordination.py:945-956` asserts that prose naming `source_id`, `source_sha256`, `private_lookup_key`, `private_lookup_map`, and `share_relative_path_private_only` passes. Existing scanned artifacts also contain such prose, e.g. `docs/plans/README.md:14` and `docs/plans/ace-share-ingestion-wave-coordination.md:17`. The plan must scope “array/list values under neutral keys” to machine-readable contract/fixture data, or define a parseable allow-context for prose; otherwise implementation either fails valid repo artifacts or weakens the stated acceptance criterion.

3. `docs/plans/2026-06-30-issue-66-ace-public-token-fixtures-private-field-placeholders.md:203`, `:261`, and `:267` create a #66 fixture token contract, but `docs/plans/2026-06-29-issue-63-ace-public-output-redaction-and-identifier-canary.md:93-106` and `:175-178` say #63 will create `config/ace-public-output-contract.json` as the shared authoritative public-token/private-field contract. #66 records #63 ownership at `docs/plans/2026-06-30-issue-66-ace-public-token-fixtures-private-field-placeholders.md:119` and `:279`, but does not specify precedence or reconciliation between the two config files. That leaves a future drift path where fixture tokens and publication tokens validate against different grammars.

## Blockers
- Finding 1: define the generation-request marker as a closed, machine-checkable grammar before implementation.
- Finding 2: resolve the “every committed artifact” contradiction by scoping private-term placement rules or defining parseable prose allow-contexts.
