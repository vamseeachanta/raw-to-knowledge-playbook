## Findings

1. **The Deliverable overstates what the firewall permits; every request that "requires #62 evidence" fails closed.** Deliverable §line 150 says the firewall will "allow metadata-only bounded sampling requests with recorded #62 evidence where required." But §Snapshot Evidence Shape (lines 213, 437) states operational downstream sampling "will fail closed with `MISSING_62_EVIDENCE_CONTRACT`" until #62 *and* #70 land, and `operational_live` evidence is "invalid in this plan." So there exists **no** accepted request that carries recorded #62 evidence — the only requests the validator ever *accepts* are the `metadata_only_fixture` self-check (`good-request.json`) and shape-only parsing. The Deliverable sentence describes an allow-path that does not exist in this approval unit. Fix the Deliverable to say the operational allow-path is deferred to #70 and this unit only accepts self-check fixtures.

2. **The firewall's accept-side is structurally untested — no positive test that a valid bounded *operational* request is accepted.** In the TDD Test List (lines 368–415), every operational/downstream test asserts *failure* (`test_downstream_sampling_requires_62_snapshot_evidence`, `…_fails_with_missing_62_evidence_fixture`, `…_blocked_until_70`, `test_placeholder_snapshot_evidence_fails`, and all `test_*_class_is_denied`). The only PASS assertions are for `metadata_only_fixture` self-check and shape-only *parsing*. Consequence: a validator that erroneously **rejects all bounded operational sampling** would pass the entire suite. For a control whose stated purpose is "reject unbounded … while allowing bounded" (line 150), the "allowing bounded" half has zero executable coverage. This is acceptable only if the plan explicitly states operational-accept coverage is deferred to #70 — it currently does not.

3. **The CI/self-scan public-path list is an unbounded, hand-maintained enumeration for a control whose whole point is "cannot omit a public artifact."** Pseudocode line 331 and acceptance criteria lines 442/445 require the parent scanner to run over "retained plan-67 review artifacts" via explicit `--scan-public-path` entries, and lines 265/317 forbid any whole-directory exemption. The retained artifact set grows by four files every review round (already 28 at r7). `test_public_scan_paths_cover_67_artifacts` (line 411) checks the list at write-time but nothing keeps the enumerated list synchronized with the still-growing `scripts/review/results/` directory across future re-review rounds — the test passes green while the next round's artifacts silently escape the scan. The plan needs a sync mechanism (e.g., a globbed manifest the test derives coverage from, still line-scoped) or an explicit rule that new review artifacts block CI until enumerated.

4. **`test_validator_refuses_private_reads_when_ace_share_root_is_set` (line 385) is vacuous as specified.** The plan states the validator "will pass with `ACE_SHARE_ROOT` unset" (line 46) and never reads private source content — i.e., there is no code path that touches the root at all. The test mocks `open`/`stat`/`iterdir`/`glob`/existence under a sentinel tree and asserts none fire. With no read logic to begin with, the test passes even against an empty implementation and cannot distinguish a real refusal guard from its absence. Either specify a concrete attempted-access code path the guard intercepts, or reframe the test as a boundary assertion on a named refusal function rather than "no filesystem call happened."

5. **Acceptance criterion line 421 is self-referential, and the "quorum" rule (line 469) collapses to Claude-AND-Codex unanimity.** The criterion "passes adversarial plan review under the quorum rule in this plan" makes plan approval a precondition of itself. Given Gemini is structurally `UNAVAILABLE` every round (r1–r7, confirmed in `gemini-r7.md` and lines 479–497), the "at least two providers return usable no-MAJOR in the same round" floor is only satisfiable by both remaining providers clearing simultaneously — a unanimity requirement, not a quorum. State the effective rule plainly (both Claude and Codex no-MAJOR in one round) rather than "quorum," which implies a majority-of-three.

6. **(MINOR) Skill-validation invocation mismatch.** Acceptance criterion line 450 specifies `uv run python skills/validate_skill.py`, but `.github/workflows/validate.yml` line 19 runs `uv run skills/validate_skill.py` (no `python`). Harmonize the command form so the acceptance gate matches what CI actually executes.
